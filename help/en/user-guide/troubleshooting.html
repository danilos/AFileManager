Troubleshooting

A file cannot be read

AFileManager asks the file service for a user-visible failure explanation. A file locked exclusively by another process should be reported instead of producing an empty preview without explanation.

Preview is blank

Confirm that the resource type is recognised by DataTypes and that a presentation provider is available. HTML rendering in this release is still incomplete for modern web content; the help system intentionally uses documentation-style HTML.

External operation fails

Archive and other external operations may depend on AROSA services or command-line utilities. The operation status/error should identify the immediate failure. Use the diagnostic logging described below when a repeatable problem needs more detail.

Logging and diagnostics

Because this is a technology preview, diagnostic information is particularly important when reporting problems. AROSA provides a common Logging Service used by AFileManager and other AROSA applications and services. Applications publish structured diagnostic events; the Logging Service owns the persistent log files, rotation and retention.

Logging can be selected by the application descriptor and changed by the user from Configuration > Diagnostics. A launch option can temporarily override the saved level for the current application start. AROSA records the effective logging request for each application session.

Logging levels

LevelPurpose
TraceVery detailed execution flow used to reproduce and investigate difficult defects.
DebugDeveloper and detailed operational diagnostics.
InfoSparse normal lifecycle and significant operational information.
WarningA recoverable or degraded condition.
ErrorAn operation or capability failed.
FatalApplication or service integrity is at risk.

The normal preview configuration requests Info, so Info, Warning, Error and Fatal events are retained while Debug and Trace remain quiet. Audit events are retained independently of the diagnostic threshold.

Launch overrides

AFileManager --verbose requests Debug logging for that launch. AFileManager --trace requests Trace logging for that launch. These switches do not rewrite the user's saved configuration.

Log files

Each application start has its own timestamped diagnostic session so a new run does not overwrite the previous run. AFileManager logs are written under AROSA:State/AFileManager/Logs/; platform-level Logging Service sessions are written under AROSA:State/Logs/. The established AROSA retention policy limits individual log size, retained file count and total retained size.

When reporting a defect, include the log from the application session in which the problem occurred, the complete AFileManager version, the AROS build, the operation being performed, the expected and actual result, and a sample resource or screenshot where relevant.
